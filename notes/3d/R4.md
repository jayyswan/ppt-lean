# R4: does any in-PowerPoint route read the projected outline (not the projected rectangle)?

Backends: PowerPoint 16.0 COM (pywin32) for setup/readback; UIA/mouse (pywinauto) for UI; PIL/numpy for alpha boxes (96 dpi `Shape.Export`, +-0.75 pt). No Wolfram. Scratch: `...\scratchpad\R4\`.
Test shapes 300x200 at (330,170), X=-50, Y=40, fov 90 (oval, triangle, wave, open Bezier width 6); pictures from Paste Special EMF and PNG.
Frames of the oval picture: 237.72 x 302.52 (EMF), ink (alpha) box inset 9.8 to 19.6 pt from frame sides.

## Findings summary
1. **No route reads the projected outline.** Every tool tested acts on the picture *frame* (the raster rectangle); none trims to alpha. [Measured]
2. New in this build: **AI Edit Picture** (Remove Background > AI-assisted; Edit object > Cutout; Upscale; Erase). It segments the alpha/ink (white mask outline visible in the editor) but on Save the frame and crop are unchanged (237.72 x 302.52, crop 0); the mask only erodes edge pixels (ink box 28..255 vs 26..258 px of 316). EMF becomes raster. Upscale: 498x634 -> 2988x3804 px, frame unchanged. [Measured]
3. Remaining non-trim: Designer scales the frame uniformly (159x264 -> 264x439), keeps margins. Compress (96 ppi, delete cropped) bakes crop, keeps transparent margins (17/26 pt). [Measured]
4. Crop-handle drag sweep: left handle plateau at CropLeft = 10.86 pt on the oval picture, which equals the model outline-left offset (about 10.9), but a control (triangle picture, outline offset 19.6) plateaued at 67.88 then 292.89. So not a snap to ink; inconclusive artifact of my mouse sweep. [Measured, Open]
5. Not tested: Morph intermediate frames, video export, ink-to-shape, lasso/eraser, Trace/Vectorize (none seen in ribbon or Picture Format), Set Transparent Color, Manual-editing Remove Background (R2: no trim).

## Excluded by user rule (outside PowerPoint)
I opened MS Paint once (my own instance, closed without saving) before the rule arrived. Its results (paste, Crop to selection, Remove background, paste back: same aspect frame scaled 1.565x, no trim; Paint flattens alpha to white) are excluded. No Word, Excel, OneNote or Photos routes were run by this stream.

## Other things noticed
* Ribbon: Edit Picture and Erase buttons, Picture Quality (Compress/Upscale) are new AI features; UIA ListItem click_input fails in galleries, use screen coordinates.
* Importing pywinauto breaks win32com in the same process; use separate processes.
* Escape deselects a picture and drops the Picture Format tab.
