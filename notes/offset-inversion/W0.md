# W0 — Wolfram atlas for offset inversion

Stream W0 of `PLAN-offset-inversion.md`. Deliverable: `atlas.wl` (self-contained) and this
note. No `.lean` file touched. Backend: **Wolfram Language** (kernel 15.0.1) via
`wolfram_WolframLanguageEvaluator`, 30–50 digit working precision.

## 0. How to load it — read this first

The Wolfram evaluator is a **Linux sandbox with no mount of the Windows filesystem**, so
`Get["C:\\dev\\...\\atlas.wl"]` does **not** work. Two workarounds, both verified:

1. **Paste** the whole file into the evaluator and append the computation. The file is
   self-contained and does not rely on package contexts, so this always works.
2. **Serve it over HTTP from the host** (`py -m http.server 8765 --directory
   C:\dev\Powerpoint\lean\notes\offset-inversion`), then
   `Get["http://<host-address>:8765/atlas.wl"]` from the evaluator. The sandbox reaches the
   Windows host; `host.docker.internal` or the host's LAN address both work depending on the
   container setup.

Everything is defined in `Global`` on purpose: a whole evaluator cell is parsed before
`Get` runs, so a `BeginPackage`/`OffsetAtlas`` context would leave the names unresolved in
the rest of the same cell.

## 1. API contract

A **curve** is an association built by `mkCurve`:

```wolfram
parabola = parabolaCurve[];            (* association with "param", "tmin", "tmax" *)
c        = mkCurve[Function[t, {xExpr, yExpr}], <|"tmin" -> ..., "tmax" -> ...|>];
```

`mkCurve` accepts `Function[v, {x, y}]`, a pair `{x, y}` with an explicit variable, or a
ready association. The stored parameter is `oaT`; every helper below takes the curve
object, never the raw parameter.

| function | meaning |
|---|---|
| `speed[c, t]` | `√(x'(t)² + y'(t)²)` |
| `tangentAngle[c, t]` | `ArcTan[x', y']` (angle of the velocity) |
| `curvature[c, t]` | `(x'y'' − y'x'')/speed³` |
| `normalVector[c, t]` | `(−y', x')/speed` (the `Defs.lean` normal) |
| `whewell[c, t]` | `{ψ(t), s(t)}` where `s` is arc length from `tmin`, symbolic where possible |
| `offsetCurve[c, d]` | the offset as a new curve |
| `offsetPoint[c, d, t]` | the offset point at a numeric `t` |
| `cuspParams[c, d, {a, b}]` | roots of `1 − d·κ(t)` in `[a,b]`, i.e. offset cusps |
| `offsetArc[c, d, {t0, t1}]` | offset arc length, `NIntegrate[Abs[1 − d κ(t)] speed(t), …]`, with the true-offset parametrisation as `Method -> "Direct"` |
| `offsetInvert[c, d, t0, x]` | solves the monotone-window equation `offsetArc[c,d,{t0,t1}] == x`; returns `{t1, x, residual, converged, cusps}` and reports any cusp in the window |
| `checkIdentity[lhs, rhs, pts]` | residuals at 40-digit precision (`$MaxExtraPrecision` raised); returns `{point, residual}` pairs and the max |
| `parabolaWhewell[w]` | `(w√(1+w²) + asinh w)/2` |
| `parabolaOffsetArc[w, d]` | `parabolaWhewell[w] − d·arctan w` |

Curve constructors: `parabolaCurve[]`, `powerLawCurve[a, p]`, `ellipseCurve[a, b]`,
`expCurve[]`, `shearedSineCurve[a, b]`, `cubicBezierCurve[p0, p1, p2, p3]`.
`parabolaSelfTest[]` runs the W0 acceptance test and returns an association of results.

`offsetArc` uses `Abs[1 − d κ]` **honestly** (it is not the signed `1 − dκ`), and
`offsetInvert` searches on cusp-free windows, returning the cusp report rather than silently
crossing one.

## 2. Acceptance test (the source note's parabola checks)

Command:

```wolfram
Get["<atlas.wl>"]; parabolaSelfTest[]
```

Symbolic checks, all exactly `0`:

- `D[parabolaWhewell[w], w] − Sqrt[1 + w²]`
- `D[parabolaOffsetArc[w, d], w] − (Sqrt[1 + w²] − d/(1 + w²))`
- `ψ'(t) − κ(t)·speed(t)`
- `d/dt tan(ψ(t)) − 1` (the Jacobian `dw/dt = 1` for the graph `t = x = w`)
- the `Abs`-free arc element on `d < 1`
- `Maximize[κ] = {1, {w -> 0}}`
- `Reduce[D[parabolaOffsetArc[w,d],w] > 0, d < 1]` ⇒ `Element[w, Reals] && d < 1`

**Residuals of `parabolaOffsetArc[w,d]` against `offsetArc` of the numeric offset**, at
50-digit working precision (formula and `"Direct"` method agree):

| `d` | `w` | residual |
|---|---|---|
| `1/2` | `7/10` | `0``50.047` |
| `1/2` | `3` | `0``48.998` |
| `−3` | `7/10` | `0``49.286` |
| `−3` | `3` | `0``48.726` |
| `9/10` | `7/10` | `0``50.390` |
| `9/10` | `3` | `0``49.043` |

(`0``a` = zero to `a` decimal digits.) These reproduce the source note's "residual 0 to ~39
digits" at higher precision.

**Cusps** (zeros of `1 − dκ`) on `[−5, 5]`: none for `d ∈ {1/2, −3, 9/10}`; `{0}` for
`d = 1`; `±0.7664209365…` for `d = 2`; `±1.0392708131…` for `d = 3`. This matches the
cusp-free claim for `d < 1` (`κ ≤ 1`).

**`offsetInvert` round trip** (`d = 1/2`, target `L_{1/2}(3)`): `t1 = 3 − 4.34×10⁻³⁰`,
arc matches to 30 digits, `residual = −1.35×10⁻²⁹`, `converged = True`, no cusp crossed.

## 3. Usage examples for later streams

```wolfram
(* 1. Whewell function of the ellipse, symbolically/numerically *)
c = ellipseCurve[2, 1];
whewell[c, 7/10]

(* 2. Invert an offset arc: where does length 1.3 end on the offset of the parabola by 1/2? *)
offsetInvert[parabolaCurve[], 1/2, 0, 13/10]

(* 3. Check an identity at three points, 40 digits *)
checkIdentity[parabolaOffsetArc[w, 1/2],
              offsetArc[parabolaCurve[], 1/2, {0, w}],
              {w -> 7/10, w -> 3, w -> 11/10}]
```

## 4. Notes and bugs found while building it

- `Join` on associations keeps the **last** value for a repeated key; the cusp association
  had to be rebuilt rather than joined.
- `Subdivide` returns exact rationals, so a `NumericQ` filter silently discarded every
  sample; the sampling code now applies `N` first.
- The initial bisection cap of 80 halvings limited `t1` to about `4×10⁻²⁵`; it now uses a
  scale-aware stopping rule.
- `NIntegrate` runs at `wp + 10` internally because `Abs` at a cusp reduces the achievable
  precision.
- The first cusp rule was keyed on the wrong variable (`oaT` instead of `FindRoot`'s
  variable); fixed.

Complete and verified against the acceptance test. The only limitation is the sandbox
