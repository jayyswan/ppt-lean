## Findings summary

1. **Window law (all three circular presets) [Proof from W + F1, Wolfram].** An edge with ink-box data
   `a = Δu`, `h = Δv`, `w₀` = lowest radial fraction (Circle/Up: `w₀ = v₀`; Down, where ink top goes to the
   inner circle: `w₀ = 1 − v₀ − h`) becomes the window `ψ ∈ [ψ₁, ψ₁ + Θa]`, `ψ₁ = Θ a (κ + w₀)/h`, with
   (Θ, κ) = (2π, 1) Circle, (π, 1) Arch Up/Button, (π, 1/3) Arch Down. Hence ideal windows (any rational
   `a, h, w₀`): Circle `{ψ₂ ≤ 2ψ₁, ψ₂−ψ₁ ≤ 2π}`, Up `{ψ₂ ≤ 2ψ₁, ψ₂−ψ₁ ≤ π}`, Down `{ψ₂ ≤ 4ψ₁, ψ₂−ψ₁ ≤ π}`.

## 1. Reachable windows, derivation and numbers

### 1.1 Formula
From W (Circle) and F1 (Arch, Θ = π): the guide maps `(u, v) → angle Θ u + const`, radius `ρ + (R − ρ) w` with
`ρ/(R−ρ) = κ` (1 for ρ = R/2, 1/3 for ρ = R/4). A straight edge `u = u₁ + a s`, `w = w₀ + h s` is the spiral
`r ∝ ψ` with `ψ = Θ a (κ + w₀ + h s)/h`: window `[Θ a (κ+w₀)/h, Θ a (κ+w₀)/h + Θ a]`, ratio `1 + h/(κ + w₀)`
[Proof; Wolfram `Simplify` = 0 in F1]. `a, h, w₀` are fractions of the whole **row** ink box [Measured-from-F1]:
`a = (edge Δx)/(row ink width)`, `h = (edge Δy)/(row ink height)`, `v₀ = (edge bottom − row ink bottom)/row ink height`.

### 1.2 Model of a row (so the numbers are reproducible)
Size S pt → `ppem = round(4S/3)` px; ink width `= (x₁−x₀)/upm × ppem` (unsnapped); advance `= round(adv/upm × ppem)` px
+ k px of spacing (k integer: presets -4, -2, 0, +4, +8 px, spinner any k). Checked against F1's numbers: fallback ◢
(72 pt: advance 80 px → 60.0 pt; 96 pt: 106.67 → 107 px → 80.25 pt; ink 0.679 em) and Segoe UI Symbol ◢ (ink 1434/2048 em = 50.41 pt
at 72 pt ✓, advance 1764/2048 × 96 = 82.7 → 83 px = 62.25 pt ✓). Row of n equal glyphs: `W = (n−1)m + w`, `m` = advance + spacing.
Mixed rows: all glyphs share one baseline, ink box = union of ink boxes (vertical positions not pixel-snapped; error
≲ 0.5 px, so I demand a 1 % margin of ψ on both window ends in the route table).

### 1.4 What is not covered
- ψ < 0.0018 (spinner, n ≤ 40) and the origin. ψ > ≈ 50 with the swept recipes.
- **Not swept [Open]:** Stacked direction with wide polygons (F1: `u` runs along the stack, `v` across the glyph, so a
  wide parallelogram such as ▱ has `a = Δy/L`, `h = Δx/W`, `a/h` up to the glyph aspect); baseline offset in the
  Font dialog (raising one run changes the row height without changing the width, so `a/h` is then unbounded in principle);
  flat slanted edges found by W in Cascadia/Arial symbol blocks (`q₂` up to ≈ 20, ψ ≈ 131). None measured in PowerPoint.

## 2. Root counts with an enclosure method

Method [Wolfram]: bisect `[0.05, 30..48]`, enclose `f` and `f'` with `Interval` arithmetic; a cell with `0 ∉ f(I)` is
discarded; `0 ∉ f'(I)` and a sign change certify exactly one simple root (then refined to 40 digits); otherwise bisect to
width 1e-7 and, at a surviving cluster, solve `f' = 0` and test `|f| < 1e-20` (double root) or report a non-root cluster.
No cluster survived in any of the 77 families, i.e. there is **no tangential root in the sampled members** and every
sign-change count of I1/I2/I3/F3 is exactly right. Equations (`c = cos θ`, `s = sin θ`; power laws in squared form with the sign
filter `c > 0`, `s ≷ 0` of the branch; checked against the original counts):
I1 rows as in I1's table (the affine-image case with `Re(Ae^{2iθ})` written out: `θ²(3 + cos 2θ + 2 sin 2θ) + 4θc − 7`);
I2 rows; I3 exp `θ sin(θ−β) = 2^{θ cos(θ−β)}` and the sine variants (trivial roots `mπ` kept); F3 (G) with `M, c, P` of F3 §1,
focal parabola, focal hyperbola with the `x+1 > 0` filter, focal ellipse, graphs of F3 §3, nodal Béziers (`a θ c³ + (1+am)c² = 1`, `c = cos(θ−1/3)`),
and the focal cubic Bézier solved in the Bézier parameter `t` (`Im[z e^{−i|z|}] = 0`, `Re > 0`, `θ = |z|`).
Result per family: identical to the note's count in (0, 4π] and, for the infinite families, 2 roots per turn beyond.
Interesting side results:
- I3 exp `β = π`: the 4th root `12.5663574941714856…` lies `1.3·10⁻⁵` below 4π (and `β = 0`: `9.42462356…` is `1.5·10⁻⁴` below 3π).
  A pure Circle window cannot place such a root with a tolerant margin; route table uses a mixed row.
- Trivial sine roots `mπ` (E): `4π = 12.5663706143591729538506` is the exact top edge of ◢'s Circle window.
- Roots at 2π±0.03 (`xy = 1`, `−1/x`, `x^{-2}`, `x^{-1/2}`, exp π) sit on the boundary where ◢ and ▲ windows touch; they need a window
  straddling 2π (found: ◢ rows with condensed spacing, `2 × ◢`, −30 pt).
- Fold of `θ sin θ = A sin(θ cos θ)` at A ≈ 2.95359: roots merge there; `restrict` isolation gets hard just above it.

## 3. Root audit

### 3.1 Summary
- 343 roots (I1 85, I2 94, I3 85, F3 56, M 23): **0 unreachable**. 88 need a mixed-height row (all with θ > 12.49 or within 1 % of 2π/4π
  or of a window edge of every pure row). Roots between 16 and 46 of the infinite families were not tabulated; they are reachable by the
  mixed-row recipe up to ≈ 36 (2 % robust) / 44 (0.5 % robust) and not by anything swept above ≈ 50.
- **Heuristic caveat**: rows on Arch presets rest on the single-glyph measurement; the Circle routes (rows) rest on the measured
  whole-row rule. The table prefers fewest glyphs, Circle on ties; where it picks ArchDown/Up n=1 it is exactly F1's measured case.
- Unreachable in principle: roots with `θ < 0.0018` (none listed), roots with `θ > ≈ 50` (infinite families have them; they
  are not needed since each family's roots are 2π-periodic up to O(1/θ) and reachable ones already determine the pattern).
- Roots that are E/R anyway (line through centre, Dottie 0.7391, Kepler, trivial `mπ`, `x sin x = 1`, focal families) need no window:
  they are listed because I1-I3-F3 listed them; reachability by the spiral only matters for the `?`/N classes.

## 4. Unreachable roots and why
None of the 343 tabulated roots is unreachable. The list of things that are:
- ψ below the smallest window (0.0018 with spinner spacing, n ≤ 40; ≈ 0.005 for n = 100 with Down): no listed root.
- ψ above ≈ 50 for the swept mixed-row recipe (≈ 36 with a 2 % margin): the later roots of the infinite families
  (I1 lines/hyperbolas, I3 exp/sine, box `tan` families all have roots at every 2π or π). Their *pattern* is already
  fixed by the first ones, but the individual root is out of reach for modest constructions.
- Box roots with `|tan y|` < 0.055 (y within 0.055 of `nπ`) or `> 40` (within 0.025 of `(n+½)π`): e.g. `tan y + y = k`
  with `k` near `nπ`.
- **Roots with a fragile window**: `12.5663574941714856` (exp β = π), `12.5600314767550748` (−1/x), `6.2811381` (exp π),
  `6.2576366` (−1/x), `6.2872091` (x^{-2}), `6.3083247` (1/x), `6.3458433` (x^{-1/2}). Reachable only with a window that
  straddles 2π or 4π by more than the 0.1-0.25 % pixel noise: condensed ◢ rows and mixed-height rows provide one.

## Other things noticed
- Same-size `◢|` already beats 4π: ψ ∈ [≈7.6, ≈12.2] (Arial `|`, 72 pt) and [≈8.3, ≈13.0] (Segoe `|`). W's "beyond 4π needs flat edges
  or rotated text" is unnecessary; F1 showed rotated text adds nothing, and mixed heights are the cheapest route.
- A sub-window can always be taken instead of the full one if `restrict` isolates sub-arcs ([Open] from W). The table assumes
  the *full* edge arc and only requires that the target θ lie in it with margin; the intersection point is then isolated by
  `restrict` on the *partner* side (the arc is a graph in ψ, so a rectangle around the known crossing is enough).
- Arch Down ◢ n=1 `[π/3, 4π/3]` is the single most useful window: it holds 67 of the 343 audited roots (all roots in [1.05, 4.19]).
- The window of a ▲ edge on Arch Up, `[π/2, π]`, and ◢ on Arch Down, `[π/3, 4π/3]`, overlap with the Circle `[π, 2π]`; the union
  of the three single-glyph windows already covers `[π/6, 4π]` without a gap (`[π/6,2π/3] ∪ [π/3,4π/3] ∪ [π/2,π] ∪ [π,2π] ∪ [π,2π] ∪ [2π,4π]`).
- All 12 I3 sine/exp families have non-tangential, well-separated roots except the `A = 3` pair and the exp roots next to `mπ`
  (exponentially thin, `2^{−mπ}/mπ`).
- `(x+β) tan x = 1` and `tan y + y = k` families are *monotone parameter maps*: for each θ in the audited set a unique β/k exists,
  `β = θ − arctan(1/θ)`, `k = θ + arctan θ`; the audit therefore asks only whether θ is reachable, not the parameter.
- Not checked: Button Pour with 2-3 lines, Ring/Can presets (ellipse guides), non-square boxes for arch presets, 360° box-size
  rule for the arch presets (F1 gives the sizes; no rule), pixel-snap error of mixed-height rows (modelled, not measured).
