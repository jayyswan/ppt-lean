## Verdict

**No two-curve operation, no non-constant offset, no (BD) family found.**
- Morph is the only candidate with the right shape for (i), a linear blend of two user curves. It fails on two
  independent counts: the weight w is a clock value, not a P-number, and no vector intermediate frame is readable.
- The text-warp map is a genuinely non-affine plane map, but its input is a glyph only and its guides and weight are
  fixed presets (item 2).
- Everything else is raster, a fixed preset, or a discrete family.
Nothing here is a new constructor.

## 1. Morph

| Question | Result |
|---|---|
| Interpolation rule | [Heuristic] Matched shapes are moved by interpolating geometry over time (for freeforms, matched path nodes); a linear blend (1-w)A + wB is the natural reading. Not observed as vector, so unconfirmed. |
| Intermediate frame as vector? | [Measured, Z1] No. During a windowed show the object model reports the final slide's nodes, Left and Top at every poll; `Slide.Export` gives slide state, not a transition frame. The only channel is a raster screen or video capture, which is not a legal readout. |
| Controllable w? | [Measured, Z1] No. w is a function of elapsed time under a typed Duration, advanced by the show clock. A show offers no way to freeze a transition at a fraction. A perfect frame grab would give w = t/T with t uncontrolled, not a P-number. |
| Readout | A frame is a transient render, not a slide object, so it cannot come back as a curve. |
| Node-count mismatch | [Open, not measured]. Needs raster observation of a transient frame. Not worth it while w and the readout already block. |

An idealised "Morph at fraction w" would be a new constructor, not a UI one.

## 2. Text warps

| Question | Result |
|---|---|
| What is mapped | [notes/warp, Measured] Each point (x, y) of the text row goes to (1-y)T(x) + yB(x), with T, B the preset's guide curves and y in [0,1] the position in the row box. Glyph outlines are warped; no UI path warps a freeform, and Text Outline strokes after the warp. |
| Can T, B be user curves? | No. They are the preset's own curves, set by at most 1-2 handle values (`adj`). The family is bounded: a fixed shape in x per preset. |
| Do handle values take P-values? | Typed or mouse-dragged only. A drag is continuous but cannot be bound to drawn geometry, and typed numbers do not count. No. |
| Pointwise combination? | For a stroke y = g(x) in the row box the image is y' = T(x) + g(x)(B(x) - T(x)): g times a fixed preset function, plus a fixed preset function. That is a non-affine map, but the second factor is not a user curve, the input is only the glyph's own outline, and the only weight is y, set by glyph geometry. Not a sum of two user curves. |
| Verdict | [Heuristic] none of (i)-(iii). Closed. |

## 5. Equation editor

Not driven (Z1: keystroke injection disconnected the COM proxy; I did not retry). From the OpenType MATH table
[Proof sketch]: a stretchy glyph (radical, bracket, integral) is a discrete list of pre-drawn size variants, then an
assembly of fixed parts (top, extender, bottom) with an integer repeat count of the extender. The size is therefore
piecewise: finitely many outlines plus an integer. There is no continuous parameter family, and the target size comes
from a measured content box, not a free P-valued parameter. A radical's vinculum is a straight rule. Verdict
[Proof sketch]: none of (i)-(iii). Residual [Open]: rendered outlines unmeasured.
