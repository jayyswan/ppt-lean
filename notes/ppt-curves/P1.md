# P1+P2: WordArt / text-warp geometry and text-to-shape conversion

**Verdict.** *Follow Path* (Arch, Arch Down, Circle, Button) is **not** a warp: every glyph is placed as a **rigid body**
(rotation plus translation, scale 1.0000, residual 0.0000 pt), so a straight stroke stays straight and **no spiral arises** from
it. The curves come from the **two-guide-path ("Pour" and Warp-gallery) presets**, which use a *ruled interpolation* between two
guide curves, `F(u,v) = (1-v)·B(s(u)) + v·T(s(u))`. Under **Circle (Pour)** a slanted stroke becomes an Archimedean spiral arc
exactly at the glyph corners, and along the arc whenever both circles span a full 360°. The *baked* freeform (Merge
Shapes) and the live render are **Bézier approximations (category b)**; for Circle (Pour) the error is a fixed
**2.8 % of the outer radius** and does not shrink with size. The spec defines only the guide paths, not the interior map,
so there is no category (a) statement for the interior. The user decides whether (b) is acceptable.

Backends: desktop PowerPoint 16.0 build 20527. Test shapes were built by COM (`TextFrame2.WarpFormat` 0 to 36,
`ShapeRange.MergeShapes` 1 to 5). The four non-pour presets (`textArchUp/ArchDown/Circle/Button`) are **not in the COM
enum**, so I patched `prstTxWarp prst=` and `avLst` in a saved XML and reopened it (exploration only; Transform → Follow
Path writes those prst names). Geometry was read by saving a copy and parsing `custGeom` (exact EMU) with Python (numpy,
scipy, fontTools). **No Wolfram was used; every number below is Python/numpy.** I had no UI automation, so no menu click was
performed: all click paths are [Open] until someone clicks them. Scripts and data:
`C:\Users\jason\AppData\Local\Temp\claude\C--dev-Powerpoint-lean\c222b849-70f5-4b01-ad09-a19ea61d2b9d\scratchpad\P1\`
(`pp.py`, `xl.py`, `fitlib.py`, `guides.py` = ECMA guide-formula evaluator, `t*.py`).

## Findings summary

1. **Follow Path = rigid per-glyph placement** [Measured]. For `textCircle/ArchUp/ArchDown/Button`, a rotation+scale+translation
   fit of every converted glyph (`_ / | -`, `HELLO`) against the flat outline gives max residual 0.0000 pt and scale 1.00000.
   `/` and an italic `l` remain straight segments. Placement law [Measured]: pivot = centre of the glyph's advance box on a
   fixed line y0 (146.81 for 60 pt Arial in a box at 100,100); it lands on the guide circle at arclength
   `s = x_c − x_start` (angle = s/R; R fitted 199.95 for 200; start at the 9 o'clock point for default adj); rotation = tangent
   angle. Category (a) for the rigid motions. **Spiral lead via Follow Path: negative.**
2. **Pour and Warp presets are a ruled map between the two spec guide paths** [Measured]. 36 two-path presets, 10 bars of
   Arial at 60 pt: **every bar-edge anchor lies on the spec guide** (distance ≤ 0.06 pt for arc guides, ≤ 0.003 pt otherwise;
   40 anchors per preset). Bar edges are straight lines joining a point on guide 0 to a point on guide 1. The glyph outline is
   normalised by its **ink bounding box** (not the line box): `u = (x−x_l)/(x_r−x_l)`, `v = (y_b−y)/(y_b−y_t)`; top of ink goes
   to path 0, bottom to path 1. Corners of `| _ /` match `(1−v)·B(u)+v·T(u)` with parameter = **arclength fraction** of each
   guide: ≤ 0.05 pt for Circle Pour; ≤ 0.001 pt for Plain, Chevron, Triangle, Stop, Slant, Fade, Cascade; 0.05 to 0.3 pt for
   ArchPour, Curve, Inflate, Deflate; 0.8 pt for Can; 1.6 to 1.9 pt for Wave1/2; 8 to 10 pt for Wave4/DoubleWave. The worst
   cases come from PowerPoint's own arclength estimate (finding 3), not from the interpolation.
3. **PowerPoint's arclength parameter is not the true arclength for cubic Bézier guides** [Measured]. Fitting
   `s_true = a·u + b` on the 20 bar edges: a = 0.9957 (Wave1/2), 0.9785 (Wave4: the last glyph edge stops at 97.8 % of the
   path), 0.9983 (Can), 0.9993 to 0.9996 (Curve, Inflate, Deflate); a = 1.0000 for straight guides, 0.9999 for circular arcs.
   [Heuristic] PowerPoint measures guide length approximately.
4. **Closed circle guides have an off-by-one-step artifact** [Measured]. In Circle (Pour) each circle independently spans
   **360° or 352.64° (= 360°·(1−1/49))**, apparently pseudo-random in the box size W (square box; inner/outer end angle):
   W=250, 300, 375, 500, 550, 600 both 360; W=350, 450, 700 both 352.64; W=200 and 400 outer only; W=425 inner only. It does
   not depend on font size, text, or the inner-radius ratio (adj2 25, 50, 75 %). When the two spans differ, the map is not
   polar (two phasors of different frequency) and a vertical bar becomes a straight chord, not a radial segment.
5. **Slanted stroke under Circle (Pour)** [Measured anchors; form by [Proof]]. With centre C, outer radius R, inner radius
   ρ = R·adj2/100000: `Z(u,v) = C + (ρ+(R−ρ)v)·e^{i(π+2π·u)}` (clockwise on screen, start at 9 o'clock for adj1 = 180°). A
   straight glyph edge `u = u₀ + s·v` becomes `r = ρ + (R−ρ)(θ−θ₀)/(2π s)`: an **exact Archimedean spiral** (an affine image if the
   box is not square). Any ρ>0 is the pure spiral `r = bφ` rotated by `φ₀ = ρ/b`. In Arial the slash is the integer
   parallelogram (0,−25),(425,1491),(569,1491),(145,−25) in 2048/em, so for a lone `/` the left edge is `u = (425/569)·v` and the
   right edge `u = (145+424v)/569`; the left spiral turns through 2π·425/569 = 268.9°. The pitch is a **rational function of font
   integers** and is scale-free (the ink bbox normalises size). Measured for a lone `/` at W=300: anchors within 0.04 pt of the ideal image
   (0.17 pt at the seam).
6. **The baked / rendered outline is only a Bézier fit** (category b) [Measured]. Merge Shapes (and nearly identically the live
   render) splits each glyph edge at the guide's own knots (u = ¼, ½, ¾, 1 for a circle) and makes **one cubic per piece**
   from the warped control points. For `/` in Circle Pour: 11 cubics at any size; baked vs ideal polar: rms 2.13 / max 4.13 pt
   at R=150; rms 4.26 / max 8.30 at R=300; max/R = 0.0275 to 0.0278 for R = 125, 150, 250, 300, i.e. **constant relative error
   2.8 %**. Between anchors r wobbles by about 1.2 % (an underline arc ran from r = 105.4 to 108.0; the quarter-arc cubic has
   handle ratio 0.49, not 0.5523). Live render (6 px/pt export, 1 px = 0.167 pt, R=150) vs ideal: rms 1.66 / max 3.3 pt; live vs
   baked: rms 0.55 / max 1.3 pt. Straight-guide presets are within 0.1 to 0.5 pt of ideal (noise floor 0.21 pt, seen even for Plain).
7. **Merge Shapes bakes the warp** [Measured]. Union / Combine / Intersect / Subtract / Fragment of a warped text box with a
   rectangle all return `custGeom` freeforms (commands M, L, C, Z only), with no text and no live warp. Result curves match the
   pre-merge baked outline to ≤ 0.17 pt (re-splitting; 11 to 14 nodes; Fragment gave 5 freeforms). The warped text is **not**
   usable directly as geometry: its frame (shape bounds, and Paste Special → EMF picture) is the unwarped *text box*: 400.2 × 400.2 pt
   for every warp tested (Circle, Wave1, Plain, Triangle), and AutoSize ignores the warp. The baked freeform's EMF frame is its bbox + ~1.8 pt.
8. **Glyph content** [Measured with fontTools]. `| / \ _ - l I` are 4-point polygons (0 off-curve points) in Arial, Segoe UI and
   Consolas; Arial Italic `l` is the parallelogram (54,0),(360,1466),(541,1466),(235,0). Calibri, Courier, Times have curved
   outlines for most of them. Converted glyph size is `size/2048 × font units` exactly at 12, 24, 60 pt, but the effective scale is
   quantised: 99.75 % at 100 pt, 100.125 % at 200 pt, 99.94 % at 400 pt.
9. **Parameters reachable without typing** [Spec; UI confirmation Open]. Default presets are exact. Each preset exposes handles
   (`ahLst`): Circle/Arch Pour has a polar handle for start angle `adj1 ∈ [0, 21599999]` and inner ratio `adj2 ∈ [0, 99000]`
   (percent×1000); linear presets have one handle with pinned ranges (Triangle 0 to 100000, Plain 30000 to 70000, Slant
   28569 to 100000, ...). Dragging is not exact except presumably at a pinned end. **The pinned end is not usable here:**
   `adj2 = 0` made PowerPoint drop the warp (flat glyph) [Measured by XML patch], so a pure spiral through the centre is not
   reachable that way, but `adj2 = 99000` works. This does not matter, because a nonzero ρ is only a rotated spiral
   (finding 5). *Text Direction → Rotate all text 90°/270°* (`vert`, `vert270`) works with a warp (tested, same
   normalisation) and turns `/` into a different stroke slope.

## Straight guides give bilinear maps; the stroke becomes a parabola [Proof]
For presets whose two guides are straight segments (Fade, Triangle, Chevron, Stop, Cascade, Plain) `F` is bilinear in `(u,v)`, so a
straight stroke becomes a parabola arc; Slant has parallel guides, so `F` is affine. The existing class already has parabolas
through `poly_graph`, so this reaches nothing new.

## Other things noticed
- PowerPoint **crashed twice** during the session (RPC unavailable; AutoRecovered windows appeared) after a `MergeShapes` call on a
  slide that was not the current view. `MergeShapes` needs `Windows(1).View.GotoSlide(idx)`. P3 may have been affected. I closed only my own AutoRecovered/test presentations.
- The COM `WarpFormat` enum (0 to 36) contains the *Pour* variants (8 to 11 = Arch Up/Down, Circle, Button Pour) but not the non-pour Follow Path presets.
- A 2×2 dummy square was used to trigger Merge Shapes and is a separate subpath of the result (dropped in my parsing).
- A hyphen or underline fills the *whole* radial band `[ρ, R]` under a Pour warp: the ink bbox, not the line box, is stretched.
- Character spacing, kerning and size only change the `u` positions of strokes inside the normalised bbox. Text Outline is a rendering property and is not in the merged geometry.
