# P5: open sweep of the PowerPoint UI for exact curves / maps with a vector read-out

**Verdict: NEGATIVE for new curves.** Nothing in this sweep draws a curve outside the existing constructors
(`ellipse`, `rectangle`, preset arcs, `cubic_bezier`, affine closure ops). The one genuinely new fact for the
tangent-from-a-point route (M §4.3): **the perspective shadow is an exact affine map, not a homography**, so it
cannot supply rank-4 (projective images of the sine). Opaque shadows do have a vector read-out (see table), but
it is the affine image of the shape. The Curve tool and Edit Points "Smooth Point" use a Catmull-Rom Bezier rule
(Bezier chains, no new points). Several candidates (ink, equation objects in the UI, Morph, 3-D models, picture
tools, text effects on converted text) were **not driven in the UI** this session; they are reasoned from the spec
or font tables and marked [Open] where that is all there is.

Backends: PowerPoint 16.0 (UI driven with SendInput, UIA to locate, `SaveCopyAs` XML / COM to read back),
Python (fontTools, numpy) for parsing and font tables, one Wolfram call for the shear check. Scratch:
`...\scratchpad\P5\` (`lib.py`, `ui.py`, `t*.py`, `u*.py`, `an*.py`, `sa_7.json`, `snap.json`). My presentation
`p5.pptx` was closed unsaved; lock released. A windowless `Nodes.SetSegmentType` call crashed PowerPoint once
(RPC failed, instance restarted); node operations were then done only in a real window.

## What is exact and vector in the shadow route (answer to the coordinator's EMF question)

1. **Opaque, unblurred shadows become vector shapes** after Copy, Paste Special > Picture (Enhanced Metafile),
   Ungroup (twice): a Freeform (13 nodes for the ellipse) for the shadow body. Transparent or blurred shadows come out as
   raster Pictures at any setting tested (blur 0 with 80 % transparency, 50 % transparency).
2. **Plain offset shadow**: exact translation by `(dist cos dir, dist sin dir)`.
3. **Perspective preset shadow**: x' = x + tan(kx) * y, y' = sy * y (about the `algn` corner), then offset. Measured with
   kx = 800400/60000 = 13.34 deg, sy = -23 %: affine, not projective. No homography anywhere in shadows. Numbers
   introduced: tangents of rational-degree angles and rational percentages, all P-constructible.
4. The 3-D rotation route remains the only projective source and stays raster (R1 to R4).

## Other things noticed

- PowerPoint's Curve tool and Edit Points both use the Catmull-Rom family; the Curve tool's end rule is the natural
  spline one, and is different from the chart's smoothed-line end rule (P3). A single constructor `cubic_bezier` covers all of them.
- SmartArt cycle layouts give exact regular n-gons: a free (but non-new) read-out of `cos(2 pi/n)` and `sin(2 pi/n)`.
- A windowless COM `Nodes.SetSegmentType` crashed the whole PowerPoint instance; use a real window for node edits.
- Window state values: `WindowState` 1 normal, 2 minimized, 3 maximized (2 hides the window).
- Gallery items respond to UIA `invoke`, but not to a synthetic click delivered as one mouse down/up; menu items do.
- Not tested and worth a short follow-up if ink matters: Draw tab ink-to-shape and the ruler's allowed rotation
  angles; a typed-equation (Alt+=) EMF paste/ungroup to see the glyph outlines.
